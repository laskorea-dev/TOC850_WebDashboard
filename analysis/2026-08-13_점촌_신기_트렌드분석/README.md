## 찾아낸 것 (요약)

- **신기** — 일주기가 조업 시간표다. 05시 상승, 07~18시 고농도, 19시 급락.
  주간이 야간의 16배. 토·일은 평일의 1/9(평일 613~717 / 주말 66~76).
  실제 주기는 24시간이 아니라 **168시간(1주)**.
- **점촌** — 일주기라 부를 만한 것이 없다. 진폭 29PPM, 24시간 자기상관 0.14.
  골은 오전 10시경(45PPM)으로 뚜렷하나 마루는 오후~심야가 넓게 평평하다
  (16시 78.3 / 00시 77.0 — **"오후 4시가 최고"라고 단정하면 안 된다**).
- **점촌 100PPM 초과** — 9일간 5건. 이 중 **3건은 추세형**(상승 1.0~1.75h에 걸쳐 연속 2~8개
  표본이 단조 증가, 하강은 2~4h로 3~7배 느린 비대칭), **2건은 단일표본 헌팅**
  (15분 만에 200~622 mg/L·h로 튀었다 즉시 복귀).
  5건 모두 **10:57~16:30**에 발생(평균 14.2시, 우연 확률 약 0.03%) — 날짜는 불규칙한데
  시각은 규칙적인 **위상 고정**. 간헐적 배치성 유입으로 추정.
- **신기 고주파 잡음이 점촌보다 크다** — 단일표본 튐 14건 vs 점촌 2건.
  14건 중 11건이 이웃평균 200PPM 이하 저농도 구간에 몰려 있다.
  ×20 희석이 저농도에서 오차를 증폭한다는 뜻이고, **희석배수를 더 못 올리는 근거**가 된다.
- **점촌 중복 752건** — 2026-07-30 13:09 ~ 08-12 04:00 구간이 `created_at=2026-08-11T19:24:44`에
  한꺼번에 재적재됐다. **2026-08-13 삭제 완료** (`tools/dedupe_measure_logs.py`).
- **희석배수 변경은 값에 단차를 남기지 않는다** — 전환 직전·직후 `95.91(×1) → 99.23(×5)`.
  `TOC_Conc`는 이미 희석 보정된 값이다.

`trend_interval2.py`(조화회귀) / `downsample.py` / `interval.py` 결과.

| 주기 | 점촌 | 신기 |
|---|---|---|
| 30분 | 4% | 0% |
| 45분 | 8% | 1% |

| 2시간 | 21% | 3% |

**점촌 30분 / 신기 1~2시간**이 결론. 점촌은 진폭이 29PPM뿐이라 표본을 많이 모아야 곡선이
드러나고, 신기는 진폭이 1005PPM이라 성글게 찍어도 형태가 남는다.
사건의 **상승 속도**까지 보려면 30분이 필요하다(60분에서는 오차 −72~+48%, 30분에서 −17~+6%).

## 폴더 구성

```
report/
  template.html      원본. 데이터는 __PAYLOAD__ 자리표시자로 비워 둠
  payload.json       차트가 쓰는 값 (build.py / build3.py 산출)
  toc_analysis.html  위 둘을 합친 것 = 실제로 게시한 파일
scripts/
  data.json          원자료 스냅샷 (fetch.py 산출) — 스크립트가 자기 폴더에서 찾는다
  fetch.py           Supabase에서 두 지점 전량 수집
  explore.py         채널·기간·간격·희석배수 개요
  dupes.py           중복 시각 점검
  analyze.py         기술통계 · 시간대별 프로파일 · 자기상관
  daily.py           일자별 / 요일별 주·야간 집계
  period.py          주기 탐색
  events2.py         100PPM 초과 사건 분해 (events.py 는 이전 판)
  hifreq.py          단일표본 튐 비교 — "신기에 고주파 변동 없음" 검정
  downsample.py      60분에서 사건 검출력이 남는가
  interval.py        15/30/60분 상승속도 복원 오차
  trend_interval2.py 주기별 일주기 곡선 복원 (조화회귀, K=4)
  trend_k2.py        같은 것, K=2
  build.py/build3.py payload.json 생성
  _patches/          template.html 에 절을 덧붙인 1회용 스크립트. 이미 반영됨
```

## 다시 돌리려면

```bash
cd scripts
python fetch.py            # data.json 갱신 (Supabase 접속정보는 ../../../uploader_config.json)
python analyze.py
python trend_interval2.py
python build.py && python build3.py   # payload.json 갱신
```

리포트를 다시 만들려면 `report/template.html` 의 `__PAYLOAD__` 를 `payload.json` 내용으로
치환해 `toc_analysis.html` 로 저장한 뒤, 위 아티팩트 URL로 다시 게시한다.

## 주의

- `trend_interval.py` 는 **쓰지 말 것.** 측정 시각을 15분 격자에 접는 방식인데,
  실제 타임스탬프가 :00/:15 에 정렬돼 있지 않고 날짜마다 분이 밀려 결과가 깨진다
  (점촌 1시간에서 진폭오차 424% 같은 허수가 나온다). `trend_interval2.py` 가 그 수정판이다.
- 스크립트는 자격 증명을 담고 있지 않다. 전부 `uploader_config.json` 에서 읽는다.
  생성물 HTML 에도 키가 들어가지 않는 것을 확인했다.
- **경보 임계치(`toc_alert_high`)를 경보 기준으로 읽지 말 것.** 두 지점 모두 경보를 쓰지 않으며,
  그 값은 대시보드 차트의 Y축 상한을 잡으려고 임의로 넣어둔 것이다.
- 8/13 부터 측정 주기가 15분 → 60분으로 바뀌었다(고객 요청). 또 08-12 20:00 ~ 08-13 11:02
  사이 15시간이 비어 있다. 이 구간을 포함해 재분석할 때 감안할 것.
