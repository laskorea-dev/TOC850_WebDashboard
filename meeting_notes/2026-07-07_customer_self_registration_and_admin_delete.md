* **일시**: 2026-07-07
* **참석자**: USER, Antigravity (AI 코딩 어시스턴트)
* **주제**: 고객이 직접 알람 수신처를 등록하고 관리자만 이를 관리/삭제하도록 역할을 분리하는 B2B 알람 관리 기능 설계 및 구현

## 1. 결정 사항

### A. 고객 자가 등록 기능 (Customer Self-Registration)
* **배경**: 관리자가 모든 고객의 메일 주소와 텔레그램 ID를 대신 모아서 수동으로 등록해주어야 하던 비효율을 해소하고, 고객 담당자가 직접 본인의 연락처를 대시보드에서 등록할 수 있도록 개선합니다.
* **해결책**:
  * 메인 대시보드 화면 상단에 **[🔔 알림 수신 등록]** 버튼을 배치합니다.
  * 비밀번호 입력이 필요 없는 공개형 모달을 열어, 고객이 본인의 **이름 (예: 홍길동 대리, 설비관리팀)**, **알림 수단 (이메일/텔레그램)**, **수신 주소 (이메일 주소 또는 Chat ID)**를 직접 기입하게 합니다.
  * 입력된 정보는 `site_config_v2` 테이블의 JSONB 컬럼인 `toc_alert_high.receivers` 배열 내에 오브젝트 형태로 구조화되어 안전하게 누적됩니다.

### B. 관리자 전용 삭제 기능 및 매핑 유지 (Admin-Only Deletion & Mapping)
* **배경**: 임의의 사용자가 다른 수신인의 알림을 무단으로 지우지 못하도록 삭제 권한을 제한해야 합니다. 또한, 삭제 시 어떤 사람이 귀속되어 있는지 한눈에 파악할 수 있어야 합니다.
* **해결책**:
  * 대시보드 설정 모달(`⚙️ 설정` - 패스코드 `850` 입력 필요) 내부 하단에 **"👥 등록된 알림 수신자 목록"** 테이블을 렌더링합니다.
  * 이 테이블에는 등록 시 기입했던 이름, 구분(이메일/텔레그램), 수신처 정보가 한눈에 매핑되어 보여집니다.
  * 일반 대시보드 접속자는 읽기만 가능하며, **관리자 모드(`?admin` URL 진입 및 언락 상태)일 경우에만 [🗑️ 삭제] 버튼이 활성화**되어 관리자만 안전하게 수신 해제 처리를 할 수 있도록 권한을 통제합니다.

### C. 완벽한 하위 호환성 유지 (Backward Compatibility)
* **배경**: 현장 PC에서 돌아가는 Python 업로더(`gui_uploader.py`)는 기존의 콤마 분리형 문자열(`alert_emails`, `telegram_chat_ids`)을 읽도록 설계되어 있습니다. 웹에서 JSON 구조를 바꿀 때 이 연동이 깨지지 않아야 합니다.
* **해결책**:
  * 웹 대시보드에서 사용자가 알림을 추가하거나 관리자가 삭제할 때마다, 현재 구조화된 `receivers` 배열을 파싱하여 **자동으로 이메일 주소들과 텔레그램 ID들을 콤마로 연결한 단순 문자열을 재생성**합니다.
  * 이 재생성된 문자열을 Supabase의 flat 컬럼(`alert_emails`, `telegram_chat_ids`)에 동시에 PATCH 함으로써, **현장 PC 업로더 프로그램의 소스코드나 로직을 전혀 건드리지 않고도** 완벽하게 동기화가 이루어지도록 설계했습니다.

## 2. 구현 결과 요약

1. **`App.jsx` 수정**:
   * `registerReceiver` 콜백 구현: 중복 입력 차단, 이메일 형식 검증, 텔레그램 Chat ID(숫자) 형식 검증 후 최신 데이터와 병합하여 `site_config_v2`에 PATCH.
   * `deleteReceiver` 콜백 구현: 사용자 확인창을 띄우고 삭제 완료 후 설정 재로드.

     * 설정 모달 내에 수신인 이름-타입-값 매핑 리스트 테이블 렌더링 및 `isAdminParam` 플래그에 따른 `삭제` 버튼 동적 제어 적용.
