# 회의록: Device ID 수동 편집 차단 및 Caution/Warning 2단계 임계치 설정 고도화

* **일시**: 2026년 07월 07일
* **작성자**: Antigravity (AI Coding Assistant)
* **주제**: 계측기 uploader의 Device ID 필드 읽기전용화 및 주의/경고 2단계 경보 관리 고도화

---

## 1. 주요 결정 및 요청 사항
1. **Device ID 입력창 편집 제한**:
   * Windows 호스트명을 자동 추출하여 사용하므로 오타에 의한 데이터 오염을 예방하기 위해 GUI 입력 필드를 **읽기 전용 (Readonly)**으로 변경합니다.
   * 단, 사용자가 PC 이름을 다른 곳에 등록하거나 전달할 수 있도록 드래그하여 복사하는 것은 허용합니다.
2. **주의(Caution) 및 경고(Warning) 2단계 임계치 체계 수립**:
   * 임계값 명칭을 각각 **caution**, **warning**으로 정비합니다.
   * 채널별 설정(`toc_alert_high`) 내에 주의 임계값, 경고 임계값, 그리고 실제 알림이 발송되는 최저 등급인 `alert_level`을 함께 설정하여 단일 기준으로 일괄 관리합니다.
3. **대시보드 수치 글자 색상 분기**:
   * 대시보드 테이블 및 상세 내역에서 데이터 출력 시 임계치를 대조하여 색상을 주황색(Caution) 및 빨간색(Warning)으로 차별화해 시각화합니다.
4. **로컬 업로더 알림 발송 안정성 확보**:
   * 변경된 caution/warning/alert_level JSON 구조에서도 로컬 uploader 경보 체크 스레드가 에러 없이 정상적으로 파싱하고, 지정된 알람 발송 레벨 기준에 따라 안전하게 트리거되도록 수정합니다.

---

## 2. 작업 완료 및 구현 세부 사항

### A. 파이썬 GUI 업로더 (`gui_uploader.py`)
* `device_id_entry` 위젯에 `state="readonly"` 설정을 부여하여 사용자가 키보드로 편집할 수 없도록 방지하되, 마우스 드래그 및 복사 단축키(Ctrl+C)는 동작하게 개선 완료.
* `check_and_send_alerts` 메소드 내 임계치 비교 로직을 리팩토링하여 채널별 `alert_level`에 명시된 등급(caution 또는 warning) 기준으로 알림 메일/텔레그램이 트리거되도록 2단계 분기 적용 완료.

### B. 웹 대시보드 (`dashboard/src/App.jsx`, `LegacyApp.jsx`)
* **설정 모달 및 관리자 설정 화면**:
  * 채널별 설정 리스트에 `주의 기준치 (ppm)` 인풋, `경고 기준치 (ppm)` 인풋, `알람 발송 기준` 셀렉트 박스(`주의 이상` / `경고 이상`)를 추가하여 Supabase `device_config`의 JSONB 필드에 정형 구조로 갱신 저장하도록 연동 완료.
* **TOC 농도 실시간 텍스트 색상**:
  * `getAlertStatus` 헬퍼 유틸을 개선하여 `status` 결과값(`caution` / `warning` / `normal`)을 리턴하도록 수정.
  * 측정 이력 테이블 및 어드민 데이터 목록에서 수치 색상 분기 처리 (주의: 주황색 `orange`, 경고: 빨간색 `var(--accent-rose)`).
  * 주의 및 경고 등급에 따라 해당 행 옆에 주황색/빨간색 알림 도트(alert-dot)를 다르게 표기하여 시각적 직관성 배가.

### C. 컴파일 및 패키징 배포
* 웹 대시보드 프로덕션 빌드 완료 (`dist/` 번들 재생성).
* `pyinstaller`를 사용해 `gui_uploader_v5.2.exe` 무설정 단일 바이너리 빌드 완료.
* 배포 패키지 디렉토리를 `계측기_PC_배포패키지_v5.2`로 분리하여 실행 파일, 배치 실행 스크립트, 그리고 설정 매뉴얼(`README.md`)을 최신 버전 기준으로 업데이트 동기화 완료.

### D. 등록되지 않은 장치/지점 접속 통제 (보안 우회 보완)
* **기존 문제점**: URL에 아무 장비 ID(`?device=invalid_id`)나 마구잡이로 입력하더라도 설정 로드 실패 시 하드코딩된 패스코드 `'850'`으로 로그인 게이트를 우회 접속할 수 있었던 결함을 보완했습니다.
* **해결책**:
  * `siteConfig` 초기값에서 하드코딩된 패스코드 `'850'` 폴백을 완전히 제거했습니다.
  * Supabase `device_config`를 조회했을 때 데이터가 존재하지 않는 경우 `isValidDevice: false` 상태로 설정합니다.
  * `isValidDevice === false` 인 경우 대시보드 화면 및 로그인 폼 렌더링을 즉시 중단하고 **"🔒 접속 제한: 등록되지 않은 계측 장비 또는 지점 ID입니다."** 경고 안내 카드만 렌더링하도록 예외 처리를 통합 완료했습니다. (App.jsx 및 LegacyApp.jsx 공통 적용)
