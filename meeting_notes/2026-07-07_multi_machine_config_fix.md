# 회의록 (Meeting Notes) - 2026-07-07

## 1. 개요 및 안건
* **일자**: 2026-07-07
* **안건**: 다중 계측기 PC 환경에서 업로더 구동 시 Supabase `site_config_v2` 테이블의 지점 설정 레코드가 중복 덮어씌워지는 오류 현상 조치

## 2. 현상 및 원인 분석
* **문제 상황**: 업로더 프로그램을 복사하여 신규 PC에 설치하고 설정 변경 시, Supabase 원격 설정 테이블(`site_config_v2`)의 기존 등록 레코드가 다른 기기의 정보로 덮어씌워짐.
* **원인**:
  1. 배포 패키지 디렉토리(`계측기_PC_배포패키지_v5.1`) 내의 `uploader_config.json`에 `site_id`가 `"Desktop-Wansu"`로 하드코딩되어 고정되어 있었음. 이로 인해 다른 PC에서도 기본 식별자(`site_id`)가 항상 `"Desktop-Wansu"`로 통일되어 작동함.
  2. 업로더 GUI 화면에서 실제 Supabase의 고유 매칭 키인 `site_id`를 수정할 수 있는 입력 창이 부재했고, 컴퓨터 호스트네임인 `device_id` 필드만 읽기 전용(`readonly`) 상태로 노출됨. 이로 인해 사용자가 물리 PC별 고유 식별자 ID를 GUI 상에서 정상 입력/수정할 수 없었음.

## 3. 결정 및 조치 사항
* **설정 자동화 및 수정 권한 복구**:
  1. **배포 설정 리셋**: 배포용 템플릿(`계측기_PC_배포패키지_v5.1/uploader_config.json`)의 `site_id`, `site_name`을 `"auto"`로 리셋하였습니다. 이제 신규 PC에 복사하여 최초 구동 시 자동으로 해당 PC의 실제 윈도우 호스트네임을 식별하여 고유의 `site_id`로 자동 할당하며 덮어쓰기를 원천 방지합니다.
  2. **GUI 설정 인터페이스 보완**: 읽기 전용이던 UI 영역에 **지점/기기 식별자 ID (Site ID - 고유값)** 입력창을 정상 노출하고 편집 가능 상태(`state="normal"`)로 변경했습니다. 이제 사용자가 각 PC마다 고유하게 명명할 기기 ID(예: `TOC-260706-03` 등)를 GUI에서 자유롭게 입력하고 적용할 수 있습니다.
  3. **실행 파일 빌드 및 클리닝**: 수정 사양을 반영하여 `gui_uploader_v5.1.exe`를 재빌드하고 배포 패키지 내부에 교체 업데이트했습니다. 패키지 내부에 쌓여있던 임시 로그 파일(`uploader.log`)도 깔끔히 정리했습니다.
