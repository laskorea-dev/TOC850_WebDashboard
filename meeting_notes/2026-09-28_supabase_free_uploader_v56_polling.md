## 2. 발견 사항

1. **Log Ingestion 이 Free 한도의 178%** — Egress 만 보면 여유였으나, 2027년 초부터 적용될 로그 한도(1GB/월)를 넘는 페이스였다.
2. **원인은 7월 빌드 업로더 2대** (삼양 인천 `TMSTOC-241224`, 점촌 `TOC-260706-01`) — 원격 테스트 메일 신호를 10초마다
   조회하던 옛 기능(`bg_check_test_alert_trigger`, 7/8 삭제)이 남아 전체 요청의 64%를 차지했다.
3. **v5.5 exe 에는 원격 관리 기능이 없었다** — 9/7 09:35 빌드가 원격 관리 커밋(`fa8f5f7`)보다 앞섰다. 버전 번호만 같았다.
4. **경보는 업로더가 아니라 서버에서 나간다** — `measure_logs_v2` AFTER INSERT 트리거 `trg_send_alert_on_insert` →
   pg_net → 테스트 배포 `dashboard-ochre-two-35` 의 `/api/send-alert`. 콘솔 Database Webhooks 화면에 보이지 않아
   한때 "Webhook 없음 → 교체하면 경보가 끊긴다"고 잘못 안내했다가 정정했다.
5. **콘솔 Logs 화면은 Log Query 를 많이 쓴다** — 원인 조사로 9/28 하루 39GB(한도 100GB/월). 평소에는 열지 않는다.

## 3. 조치 및 효과

| 조치 | 효과 (실측) |
|---|---|
| 업로더 v5.6 교체 (9/28 삼양·점촌, 9/29 나머지 3대) | 로그 59 → 약 20MB/일 (-64%), Egress 38 → 약 12MB/일 (-66%) |
| Free 복귀 | 월 $25 → $0. 한도 대비 트래픽 7% · 로그 60% · DB 8% |
| 고객용 대시보드 조회 개편 (`346e371`, `b495b4c`) | 화면 1개 하루 576건 → 약 144건. 최신값 지연 최대 15분 → 약 90초 |

대시보드 조회 개편 내용:
- 측정 데이터는 최근 서버 수신 시각(`created_at`) 기준 **업로더 주기의 다음 배수 + 90초**에 조회한다. 주기는 최근 수신
  간격의 중앙값으로 추정한다(1시간 측정 현장은 1시간). 업로더를 일시정지·재시작해도 새 데이터를 받으면 다시 맞춰진다.
- 설정은 30분마다(화면이 보일 때만). 새로고침·탭 전환 최소 간격 5분. '새로고침' 버튼은 즉시 조회.
